## Context

Skopos already has plan, mission, decision question, recommendation, finding, and closure artifacts. The problem is that an agent can still start coding without invoking those surfaces. When that happens, Skopos may only warn later through trust or closure checks, after the durable memory opportunity has already been missed.

The Pack Gates V1 implementation exposed this gap. The work touched model, runtime, CLI, UI, policy packs, release smoke, and accepted self-policy. That was not a light task, but the workflow record was not created before implementation.

## Decision

Skopos must treat workflow recording as a preflight concern for non-light work.

Generated plans and missions must include an explicit workflow-recording step when the work is broad, risky, or cross-cutting. The step must tell the agent to confirm the lane before editing and to record durable decisions or findings when project truth changes.

## Rules

1. Light work may stay lightweight and does not need a mission-only ceremony.
2. Normal and workpack work must keep plan and mission state current.
3. Work that changes durable product, architecture, workflow, release, or policy truth must add or update a decision.
4. Work that discovers a structural/product gap must add or update a finding, even if the same slice fixes it.
5. Trust and closure checks are not enough by themselves because they happen too late for pre-edit memory capture.
6. The guard must be generated by Skopos planning/runtime behavior, not left only as prose in `AGENTS.md`.

## Consequences

### Positive

1. Agents get a concrete checklist item before coding starts.
2. Cross-cutting work is less likely to disappear into chat history.
3. The UI and CLI explain why a mission, decision, or finding was expected.
4. Small tasks can still avoid heavy ceremony.

### Tradeoffs

1. Some workspace-scoped tasks will show one extra workflow item.
2. The first version is heuristic-based and may need tuning as more project types use Skopos.
3. Full enforcement still depends on coding host adapters invoking Skopos at session start and stop.

## Proof

The CLI e2e plan coverage must prove that high-impact work includes a `record-workflow-lane` implementation step, a `step-record-workflow-lane` mission item classified as workflow work, and human-readable workflow-recording guidance in text output.
