# Structure

Define the interface job before styling. Project audience, terminology, workflows,
tokens, components, assets, and approved precedents are truth.

1. Identify the primary job, decision, risk, frequency, and evidence. Choose a fitting
   surface; do not default to a dashboard.
2. Turn acceptance into a visible inventory: orientation, primary objects, decisive
   facts, states, actions, errors, recovery, and outcome. Do not simplify away a
   required item or hide the evidence needed before an action.
3. Set reading order, navigation, density, and disclosure around that job. Let order,
   type, spacing, and alignment carry hierarchy before decoration.
4. Give each string one role: orient, title, instruct, act, report, explain, label
   metadata, or recover. Use familiar words, concrete nouns, active voice, and the
   shortest complete explanation. Remove repetition and implementation detail.
5. Actions name a verb and outcome. Errors state what happened, whether work survived,
   and how to recover. Empty states distinguish start, filter, access, and failure.

## Bad to Better

| Context | Bad | Better |
| --- | --- | --- |
| Heading | `Management` | `Team access` |
| Primary action | `Submit` | `Save billing address` |
| Help | `Enter a valid value` | `Use the legal name on your tax documents.` |
| Empty | `No data` | `No invoices yet. Create one when this order is ready.` |
| Error | `Error 403` | `You don't have permission to edit this workspace.` |
| Recovery | `Something went wrong` | `We couldn't save your changes. Your work is preserved—try again.` |
| Confirmation | `Success` | `Invitation sent to maya@example.com.` |
| Technical | `Webhook returned HTTP 500` | `We couldn't sync this order. Retry or reconnect.` |

In task order, a first-time user should understand purpose, priority, actions, outcome,
and recovery. The default rendered view must contain meaningful task content rather
than navigation scaffolding alone. Read copy without code; reject vague actions,
duplication, contradictory states, false certainty, and implementation language.
