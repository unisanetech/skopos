# React Boundaries And Human Interface Copy

Keep data access and non-interactive rendering on the server when the bound framework
supports it. Add a client boundary only for state, event handlers, lifecycle behavior,
or browser-only APIs, and keep that boundary as narrow as the interaction permits.

Write interface language around the user's task:

1. use the project's domain vocabulary rather than schema, API, or implementation terms
2. do not repeat a heading in its description
3. do not explain controls whose labels and placement already make their purpose clear
4. make errors explain what happened in user terms and what the user can do next
5. reserve confirmation copy for meaningful risk, delay, or irreversibility
6. prefer no supporting sentence over generic filler

Project architecture and terminology override generic examples in this module.
