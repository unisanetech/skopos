# Good Product UI Craft Fixture

The fixture represents a task that binds real project brand, token, component, visual
capture, typecheck, and accessibility roles. It selects only task-relevant guidance,
keeps within the context budget, preserves narrow client boundaries, proves responsive
states, uses a disciplined semantic type scale and spacing rhythm, aligns content to a
small set of deliberate edges, avoids nested containment, proves scroll ownership and
interaction states, and supplies compared rendered review evidence.

Its copy keeps one task in focus, names actions by outcome, translates system behavior
into user-visible benefits and tradeoffs, distinguishes empty from error states, and
offers calm recovery without exposing implementation terms. Destructive actions name
the affected object and consequence; routine actions do not create unnecessary noise.
Before creating components, the implementation inventories the bound catalog and
records why reuse, a variant, composition, or a new owner is appropriate. New names
describe durable roles, and a page-wide copy pass gives orientation, title, actions,
status, metadata, and recovery distinct language jobs.
